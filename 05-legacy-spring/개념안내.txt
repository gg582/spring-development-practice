기본적으로 Dispatcher Servlet은 대문과 같은 역할을 한다. 핸들러 매핑을 통해 컨트롤러에서 각 엔드포인트로부터 들어오는 입력값이 어떤 메서드에서 처리될지 판단하고 서비스를 호출한다.
서비스는 Mapper(MyBatis)를 호출하고 이 MyBatis가 적절한 SQL 쿼리를 질의해서 데이터베이스로부터 정보를 가져온다.

이러한 레거시 스프링의 구조를 전체적으로 파악하기 위해서는 Dispatcher Servlet -> Handler -> Controller -> Service 순으로 추적해서 Service 부분의 큰 그림을 특히 세밀하게 그리고 이후 트랜잭션은 Mapper를 확인한다.

================================== 컨트롤러가 무엇인가 =========================================

컨트롤러 개념은 앞선 예제들에서 했던 것과 유사하다.
짧은 토막 코드를 남겨 본다.


================================== JAVA 1.8            =========================================

@Controller
@RequestMapping("/musicians")
public class MusicianController {
	@GetMapping("/hello")
		public String hello(Model model) {
			model.addAttribute("message", "Hello, spring");
			return "musician/hello";
		}
}
 ===============================================================================================


 이 코드는 /musicians/hello/ 에서 요청을 받고, message라는 데이터를 모델에 넣고, musician/hello라는 view 이름을 반환하는 것을 의미합니다.

 중요한 것은 Controller가 직접 SQL을 호출하지 않게 하는 것입니다.

=============================== Model은 무엇인가       =========================================

앞의 토막 코드에서 model.addAttribute("message", "Hello, spring"); 을 하면 JSP에서는 ${message}로 Hello, spring이라는 값을 쓸 수 있습니다.
이것이 Model이며 기본적으로 Controller와 View 사이의 데이터 전달 상자입니다.

=============================== ViewResolver란 무엇인가 ========================================

prefix = /WEB_INF/views
suffix = .jsp
라고 할 때, musicians/hello를 반환받으면 실제 뷰는 받은 값 그대로가 아닌 ${prefix} + (필요하면 / 추가) + ${original path} + (필요하면 / 추가) + ${suffix} 형태의 URI에서 서빙됩니다.
그 말은 https:/your_url_here:your_port/WEB_INF/views/musician/hello.jsp가 된다는 뜻입니다.
viewer가 뷰를 실제 jsp로 변경해 줍니다.

============================= PageController vs RestController ===================================================


레거시 시스템은 json 등의 api보다 JPA를 통해 개발된 비중이 큽니다. 이러한 상황에서 뷰 자체의 경로를 반환해서 바로 JSP를 로딩하는 것이 PageController입니다.
아래와 같이 사용하면 반환한 스트링 위치에 있는 뷰가 호출됩니다.






========================================== Java 1.8           ====================================================
@Controller
public class PageController {
    @GetMapping("/page")
    public String page() {
        return "sample/page";
    }
}
==================================================================================================================

반면 아래는 해당 엔드포인트에 말 그대로의 스트링을 반환합니다.

예를 들면,

========================================== Java 1.8           ====================================================
@Controller
public class PageController {
	@GetMapping("/page/hello")
		public String page() {
			return "Hello";
		}
}

를 하면 API 요청 시 Hello가 반환됩니다.

이러한 상황을 방지하기 위해 서비스를 사용합니다.
